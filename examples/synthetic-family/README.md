# Synthetic family example

All identities and values are invented; fixture data is CC0-1.0. No real health
data belongs here. Follow the executable [first archive tutorial](../../docs/tutorials/first-archive.md)
and [family removal guide](../../docs/how-to/manage-family.md).

Create two people even if their names are equal. Keep the returned UUIDs separate.
Import the supplied synthetic tutorial report into one explicitly selected person,
prepare, inspect and explicitly review it before committing. The tutorial's supplied
candidate is predetermined; it is not a model extraction accuracy measurement.
Then use `correct` to draft a transcription fix, review and commit; compare exact
historical/current values. Back up, plan removal, inspect/approve the digest,
remove and restore. The companion CLI journey tests execute those boundaries.

`expected-facts.json` records expected facts and check coverage for Task9 cases.
The fixture provenance CI job inventories every distributed example and test
fixture byte. Hashes detect changes; they do not certify the absence of real data.
